# CAD 建模平台完整实施步骤

日期：2026-11-10。状态：实施计划，尚未执行。依据：[架构方案](cad-modeling-architecture.md)。本文中的新模块、类、接口、工具、测试和构建目标均为拟议交付物，不代表当前已存在。

## 1. 交付目标和实施原则

交付能够让 AI 创建机械零件及曲线曲面模型的平台。人可以检查和修改建模过程、尺寸、草图和曲面；AI 可以在人的修改基础上继续工作；过程可以封装成组件，在其他工程中复用。首个几何后端为 OCCT，公共能力需要通过第二个真实精确几何后端验证。

主数据是统一的参数化设计文档。特征树、节点图、草图、参数面板、脚本和 AI 都访问同一文档命令层。节点实现支持原生操作、可展开子图和受控算法脚本。

执行原则：

1. 先打通两类代表性模型的完整流程，再扩大功能覆盖。
2. 单位、版本、事务、引用和错误结构随第一个特征一起建立。
3. AI 与人工修改在早期接入；不等全部 CAD 操作和节点界面完成才验证。
4. 每步都有可执行的退出条件，未满足则不把依赖它的能力标记为完成。
5. 确定性的几何/文档测试和真实模型调用评估分开；记录后端、操作、组件及模型配置版本。
6. 本计划只增加规划文档；现有导入器、运行库、应用行为保持当前状态，代码实施另行开始。

## 4. S01：固定样件、范围和技术验证基线

### 实现任务

1. 建立四类任务文件：机械安装板、带局部孔变体的法兰、三截面曲面外壳、周期曲面/退化边/自交等失败样例。
2. 每个任务记录自然语言要求、显式参数、设计关系、允许误差、预期人工修改、后续 AI 修改及可复用边界。
3. 机械主样件初值为 100 × 60 × 10 mm、中心贯通孔直径 10 mm。验收包含宽度改变后孔仍居中、人工新增特征后 AI 继续修改。
4. 曲面主样件以三个带稳定标识的截面构造曲面，逐步增加裁剪/缝合/加厚；初次闭环只声明已验证的参数范围。记录明确的截面方向与对应关系。
5. 建立当前工程构建与相关测试基线，记录已有失败项；保留原有工作区改动。先采集代表性模型的时长、内存和几何误差，再定性能目标。
6. 验证 OCCT 所需工具包及当前 DLL/头文件能否组合使用；评估草图求解器可嵌入性；确定第二精确后端 SDK 的可获得性和目标能力子集。

### 交付与验收

交付 `acceptance/` 任务定义、依赖版本清单、功能矩阵和技术验证报告。每个首版功能都有对应样件或失败样例；高级曲面、钣金、装配约束等未排入首版的功能明确列出。草图求解器和第二后端未定时列为风险，不将其描述为已解决。

机械板的初始体积应为 `60000 − 250π mm³`。具体测量容差按测试尺寸和所选后端配置写入任务文件，不用屏幕像素代替几何验收。

## 5. S02：建立独立 SDK 工程和依赖边界

### 实现任务

1. 新建独立 CMake 工程，建立 `cad_domain`、`cad_runtime`、`cad_backend_occt`、`cad_cli` 等目标；后续绑定和 worker 按可选目标加入。
2. 固定 C++20、编译器、运行时和 ABI 配置；Debug 与 Release 使用独立目录。通过显式路径或安装包发现依赖，避免混用已有 lib/bin 的不同构建。
3. 建立后端版本描述、函数表和对象生命周期约定。C++ 可用于内部接口，独立插件边界使用版本化 C ABI，不跨 DLL 传 STL 容器或异常。
4. 定义 `IModelingExecutor`，先实现进程内执行器；文档调用方只依赖任务接口，为后续 worker 预留数据契约。
5. CLI 可以创建空文档、报告 SDK/后端版本、列出能力；构建产物附带运行库与操作清单。
6. 建立核心测试和几何回归入口。新测试只覆盖实际契约或风险，不按类数量机械堆积。

### 交付与验收

在不启动 Godot 的情况下能够构建并运行 CLI。核心目标的依赖中没有 Godot、Python 或 HOOPS；应用绑定独立。故意放置不匹配插件时返回明确的 ABI/版本错误，而非进入几何计算后崩溃。

## 6. S03：定义公共类型、操作注册表和错误结构

### 实现任务

1. 定义带量纲的 `Length / Angle / Scalar`，双精度点、向量、坐标系与变换。新文档内部 mm/rad，显示单位独立，源单位未知时要求调用方给出解释。
2. 定义 Curve、Surface、Edge、Wire、Face、Shell、Solid、Body 与集合输出；定义多体、空结果、开放壳的处理方式。
3. 定义 DocumentId、FeatureId、ParameterId、AssetId、ComponentId、InstanceId、Revision 与 OutputRef。运行时句柄另带 backend/context/generation，不落盘。
4. 定义 Parameter、Expression AST、FeatureNode、Port、SelectionRef、Constraint、ComponentDefinition、ComponentInstance、DocumentSnapshot 和 Diagnostic。
5. 建立版本化操作注册表：操作 ID、输入/输出类型、单位、默认值、基数、参数校验、能力要求、求值器、迁移规则和帮助。
6. 生成 JSON Schema、脚本类型说明、参数面板基础信息和 AI 操作说明；几何条件另外在求值阶段检查。
7. 建立结构化诊断：`code / message / feature_id / input_path / revision / related_refs / details`。区分错误、警告、取消、未支持和引用歧义。

### 建议首批操作定义

`parameter`、`datum.plane`、`profile.rectangle`、`solid.extrude`、`solid.cylinder`、`solid.cut`、`curve.bspline`、`surface.loft`、`measure` 和 `publish`。

首版 `profile.rectangle` 是显式参数轮廓节点，不宣称已经完成任意草图约束求解。加入草图系统后可以将其展开或迁移为相应草图定义。

### 交付与验收

序列化可往返恢复类型和单位；长度与角度混用、非法连接、错误输出基数会被拒绝。同一操作的 CLI、脚本、节点和 AI 参数定义来自同一注册表。后端指针不进入公共文档数据。

## 7. S04：实现文档命令、事务、版本和保护规则

### 实现任务

1. 创建 `CadDocument / DocumentSnapshot / EditDraft / CommandDispatcher`。命令覆盖新增/删除/替换特征、连接端口、设置参数、抑制、修改选择和发布输出。
2. 所有写操作携带 `base_revision` 和 `request_id`；新增节点使用稳定 ID，批量操作作为一个事务。
3. 实现草稿状态：创建 → 修改 → 求值 → 验证 → 提交或丢弃。已求值草稿一旦再次修改，其验证和预览指纹立即失效。
4. 提交时核对当前 revision、草稿内容、求值配置和结果指纹，原子发布图和几何版本；未通过结果规则的草稿不覆盖正式版本。
5. 实现撤销/重做和命令差异。撤销生成新的单调递增 revision，恢复历史内容，不重复使用旧 revision 造成并发误判。
6. 为请求定义幂等范围和保留期：相同 request_id/内容重试返回原结果；同 ID 不同内容报错。崩溃恢复时不得静默重复应用已提交编辑。
7. 记录作者、来源和设计假设；支持参数/特征定义保护和独立几何约束。二者区分，避免把“参数没变”误认为“几何结果没变”。

### 交付与验收

两个客户端基于同一 revision 修改时，只有先提交者成功，另一方获得可理解的冲突。失败事务、重复请求、撤销重做均不丢失或重复特征。人工修改后，旧 AI 草稿不能覆盖新版本。

## 8. S05：实现 OCCT 后端的最小双主线能力

### 实现任务

1. 建立 `OcctBackend / KernelContext / ShapeStore`，统一句柄释放、异常转换、取消检查和能力发现。
2. 机械链先实现参数矩形轮廓、拉伸、圆柱、差集、结果类型检查、面积/体积查询和基础 STEP 交换。
3. 曲面链先实现显式定义的 B-spline/NURBS 曲线、截面排序/方向、基础放样、曲面体输出和测量。首批截面必须选取可可靠重建的样例。
4. 各操作返回 `KernelResult`：输出、有效性、来源历史、警告和精度信息。尚不能提供完整历史的操作明确报告追踪能力。
5. 实现精确几何检查与离散化：边线、面网格、法线、面/边映射分开返回。求值和离散化不得原地修改被其他版本共享的形体。
6. 通过 NDS adapter 复用既有导入路径，将源拓扑 ID 限定在导入资产的命名空间；重建修复记录作为来源信息，保持旧导入器单位政策。

### 交付与验收

CLI 能生成板件和放样曲面，输出精确测量及 STEP。错误轮廓、非法截面和不支持的输入返回稳定诊断。开放曲面体不会被标成 Solid。对同一输入快照求值或离散化后，之前提交的版本保持不变。

## 9. S06：实现图执行器、增量计算、保存与恢复

### 实现任务

1. 拓扑排序并检查依赖环；表达式依赖参与同一调度。草图内部约束迭代以后封装在单个求解节点中。
2. 为节点实现参数解析、几何引用解析、能力校验、执行、验证、结果发布；定义失败/阻塞/抑制/取消等状态。
3. 变更传播到受影响子图。缓存键包括操作/脚本/组件版本、有效参数、输入指纹、选择解析结果、容差和后端版本；UI 布局不参与。
4. 定义数组与基数行为；阵列作为有显式参数和实例标识的特征，不能只靠 Python 循环生成一次性的固定节点列表。
5. 任务发布携带 revision 和 generation，丢弃过期任务结果。显示旧有效模型时明确标记“预览未更新”，不将旧结果作为新草稿的成功输出。
6. 实现最小 `.cadproj`：manifest、图与参数、导入资产、组件依赖、UI 元数据；内核/网格缓存可选并可重建。
7. 保存采用临时文件、完整性检查和原子替换；资产嵌入或内容寻址，不能只保存用户原文件路径。建立格式版本和迁移入口。

### 交付与验收

改板宽后孔中心跟随表达式更新，只有依赖节点重算；修改节点位置不触发几何重算。重开工程后能继续编辑，缺失显示缓存可以重建。保存失败保留旧工程；原始导入文件移走后工程仍能使用已保存资产。

## 10. S07：建立可维护的面、边与实例引用

### 实现任务

1. 定义语义引用：特征输出、拉伸端面、由某草图边生成的侧面、指定孔壁等；区分规则本身和某次求值的匹配结果。
2. 将 OCCT 各操作可提供的 Generated/Modified/Deleted 历史转换为统一映射，保留分裂、合并和消失关系；缺失映射不能填成虚假的一对一。
3. 建立引用解析器：语义标签 → 历史映射 → 几何/邻接条件辅助匹配。规则声明基数，歧义返回候选及原因。
4. 优先用基准平面/轴定位后续特征。坐标、面积、法向等几何特征只作为受约束的辅助信息，不能静默采用最近结果。
5. 建立显示选择结构：文档 revision、输出、子形体和 instance_path；旧拾取结果先检查版本。
6. 做参数扰动回归：改变尺寸、孔数量、布尔顺序和截面，验证引用正确或明确失效。增加对称面和拓扑拆分的歧义样例。

### 交付与验收

对验收样件，相关圆角/孔引用在声明的参数范围内保持正确；超出范围时返回 BrokenReference/AmbiguousSelection。不能仅以“没有异常”作为成功。两个共享几何实例可以分别选中；删除后恢复的旧运行时句柄不能访问新对象。

## 11. S08：提供脚本 SDK 和最小人工编辑界面

### 实现任务

1. Python SDK 封装文档命令和表达式构造，提供类型提示、上下文管理事务、查询和诊断。不把普通脚本执行等同于文档隐式提交。
2. 图构建脚本产出显式节点和连接；之后图为主数据。重跑旧脚本必须以显式补丁或新文档方式处理，不能覆盖人已修改的工程。
3. 定义算法脚本节点的契约：声明输入、输出、运行环境/脚本版本和外部资产；先只使用团队维护的固定脚本。动态生成代码和不受信任脚本的执行等待 S15 的隔离方案。
4. 新增 GDExtension facade，GDScript 调用同一命令层；新建 CadDocumentController 负责应用接入，场景对象仅呈现文档状态。
5. 实现最小参数面板、特征列表、错误面板和模型预览。选择节点能预览中间结果，修改数值提交同一套事务。
6. 将 MeshPacket 和拾取映射接入 DigitalViewer；核心保留双精度，显示层按局部原点转换。后台生成数据，Godot 对象和网格资源按主线程约定提交。
7. 实现一文档多视口显示和关闭生命周期，避免关闭一个视口就销毁其他视口仍引用的文档。

### 交付与验收

同一板件/曲面可由 Python 创建，在应用参数面板修改，随后 Python 读取到最新图与尺寸。撤销在两端一致。用户可以选中并检查 AI 将来会创建的相同特征结构，不需要先开发完整节点画布。

## 12. S09：实现基础组件与第一轮人机协作

### 实现任务

1. 提供最小组件提取：选择连通子图，分析边界依赖，将外部参数/几何提升为输入，选定命名输出与基准。拒绝未声明的外部引用。
2. 保存固定版本的组件定义和依赖资产；创建实例时分配实例命名空间，支持参数覆盖与内部预览，暂不做自动升级或复杂结构覆盖。
3. 接入最小工具集合：能力/操作查询、文档摘要、创建/修改草稿、预览、任务状态、测量、验证、提交、撤销、组件查询/实例化。
4. CAD schema 从操作注册表生成，权限与现有脚本执行分开；接入现有 MCP/Plugin Bridge 传输，不通过 `script.run` 绕行。
5. 先用确定性客户端回放工具序列验证协议，再接入实际 AI 客户端完成自然语言任务；记录模型配置和调用轨迹，不能用回放成功代替 AI 成功。
6. AI 先读当前 revision、需求约束和能力，提交有限步骤的图补丁，根据诊断修正并精确测量，再按会话策略提交。

### 必须跑通的人工演示

1. AI 创建参数化板件，孔位置表达为板宽/板高的一半。
2. 人将宽度改为 120 mm，并插入一个受当前能力支持的局部特征。
3. AI 再增加一个孔或修改另一个参数，原人工修改及无关 FeatureId 保持。
4. 人提取子图为组件，在新工程创建两个不同尺寸实例，只修改其中一个。
5. 保存重开，并继续由人和 AI 修改。
6. 曲面样件执行对应流程：创建三截面放样 → 人改一个截面参数 → AI 修改另一截面参数 → 提取为可复用组件。

### 交付与验收

交付第一个面向目标的可用原型。机械和曲面两条流程都通过；人工修改能被 AI 保留、旧草稿冲突可解释、组件实例互不污染。若这里只能生成几何却无法接续修改，应先修正文档与工具契约，再扩大操作库。

## 13. S10：完善机械建模和草图系统

### 实现任务

1. 接入 S01 选定的约束求解器，封装 `ISketchSolver`；独立保存草图实体 ID、约束、局部坐标系和求解配置。
2. 按顺序实现线段/圆/圆弧，固定/重合/水平/垂直，平行/垂直/相切，长度/距离/角度/半径/等长约束。报告自由度、冲突约束和残差。
3. 从已求解草图生成闭合轮廓，处理孔洞、方向和多个区域；拒绝自交或不明确的实体输出。早期参数轮廓迁移为草图时保留 ID 映射和参数语义。
4. 增加旋转、并/交/差、分割、孔、恒定半径圆角、倒角、镜像、线性/圆周阵列。每新增一个操作，同时补 schema、历史追踪、诊断和验收样件。
5. 阵列实例使用稳定标识，加入选定实例抑制和替换接口，为法兰某个孔改成长圆孔提供正式表达方式。
6. 根据业务样件再加入有限范围的拔模、抽壳等功能；不把它们视为调用一个内核函数即可完整交付。

### 交付与验收

交付板件、法兰、支架和旋转轴类件。变参覆盖正常范围、边界和预期失败；过约束提示能定位相关约束。人可修改草图或单个阵列实例，其他实例及下游有效引用保持正确。圆角失败保留可编辑特征及上一次正式结果。

## 14. S11：完善曲线曲面建模链路

### 实现任务

1. 曲线层：解析曲线、控制点/插值 B-spline 与 NURBS、裁剪、连接、投影、求交；明确插值误差、节点/重数/权重、参数域和周期性。
2. 曲面层：解析面、NURBS 定义、放样、扫掠、旋转/拉伸曲面和基础补面。公共参数明确截面对应、闭合接缝、方向、导轨、坐标架、扭转和端部条件。
3. 拓扑层：将曲线曲面转换为具有正确边界和方向的 Face/Shell；检查二维边界曲线、缝边、退化边、内外环和多区域结果。
4. 编辑层：裁剪、分割、延伸、受限偏移、缝合、封闭成体和受限加厚。每步分别返回几何与诊断，避免在大脚本中只留下最终形体。
5. 分析层：自由边、缝隙、法向、曲率和 G0/G1 检查；G2 构造/优化仅在后端及样件已验证时开放对应能力。
6. 报告实际连续性和偏差；区分解析/数值验证与采样评估。采样检查返回策略与精度信息，不把有限采样当作任意曲面的严格全域证明。
7. 增加失败样例：截面反向、对应关系扭转、路径急弯、周期接缝、偏移/加厚自交、缺面和缝隙过大。

### 交付与验收

完成曲面外壳的曲线 → 放样/扫掠 → 裁剪 → 缝合/加厚流程。人修改一个截面或导轨后，可检查中间曲面并定位失败特征；合法范围内结果满足声明的实体有效性和几何质量要求。没有闭合的壳保留 Shell 类型，不自动标为实体。

## 15. S12：完善人工编辑和节点界面

### 实现任务

1. 特征树提供重命名、分组、回看中间结果、抑制、删除、替换和插入操作。顺序调整必须满足依赖，不能只改变树的视觉顺序。
2. 参数面板支持单位、表达式、范围、参数保护、求值状态和影响预览；用户拖动时合并更新，停止后提交一次可撤销事务。
3. 草图交互支持绘制、捕捉、尺寸标注、约束选择、拖动求解和冲突定位；区分构造几何与建模轮廓。
4. 曲面交互支持截面/导轨选择、方向与接缝调整、控制点编辑以及质量显示；只允许修改可追溯的定义，编辑源与结果预览清晰区分。
5. GraphEdit/GraphNode 绑定相同特征图，支持类型检查、单位检查、连接/断开、子图折叠/展开、搜索、错误定位与中间输出预览。
6. 三维选择反查语义特征，简单拉伸长度或孔径通过操纵器修改原参数。无法唯一反推参数时显示候选或创建明确的直接编辑特征。
7. 将移动面、偏移面等直接编辑按后端能力和选定样件逐项交付；每个操作保留选择规则、历史和失败报告。删面补面等复杂操作若未验证则不开放。
8. 实现跨面板选择同步、同文档多视口同步，以及保存/恢复 UI 布局。UI 状态不改变几何缓存和文档语义。

### 交付与验收

未参与开发的使用者可以完成四项任务：改孔径、改草图轮廓、调整曲面截面、替换一个建模步骤。无需编辑脚本即可完成；撤销后图、几何、选择与参数一致。节点图和特征树不存在两份需要手工同步的模型。

## 16. S13：完善组件、实例覆盖和版本升级

### 实现任务

1. 完善子图边界分析，把外部参数、基准、几何输入和资产提升为显式依赖。提供组件接口编辑器，定义命名输出、参数范围与设计断言。
2. 固定组件定义版本和依赖清单；工程保存依赖快照或内容寻址资源，以便脱离原工程打开。
3. 区分参数覆盖、实例内部的局部结构变体和共享定义修改。结构修改优先分叉为新组件版本/本地变体，避免隐式污染其他实例。
4. 阵列实例覆盖绑定稳定键；阵列数量减少、排序改变或实例消失时给出覆盖失效诊断，不自动套用到另一个孔。
5. 实现版本升级预览：迁移参数和端口，比较受影响特征，重算并验证引用与设计断言，通过后切换版本；失败保留旧版本。
6. 提供本地组件库：名称、用途、类型化接口、版本、预览、依赖、验证范围和示例。优先交付按分类/接口/文本检索；向量检索视真实检索需求增加。
7. 建立初始复用库：孔阵列、安装板、法兰、支架、截面生成、曲面过渡、外壳子图。组件内部以语义特征命名，不依赖聊天上下文。

### 交付与验收

组件在新工程中建立两个参数不同的实例，修改其一不影响另一实例。修改法兰的一个孔可保存为局部变体，重开仍可编辑。组件升级不静默覆盖实例参数和人的局部修改；不兼容升级能明确报告并保持旧结果。

## 17. S14：提高 AI 建模、修改和复用能力

### 实现任务

1. 建立逐级上下文查询：文档摘要 → 相关部件/子图 → 节点与参数 → 局部拓扑/测量。支持分页和按需查询，避免每次发送整个 BREP 或全部节点。
2. 建立模型无关的任务流程：读取需求/能力 → 检索组件 → 选择建模路径 → 分批修改图 → 预览 → 精确检查 → 必要时修正 → 提交。
3. 为每个操作/组件提供有效示例、参数范围、常见错误和几何含义。AI 优先表达设计关系，如居中、同轴、等厚，不仅填充当前坐标值。
4. 提供语义几何查询，返回候选、匹配条件和基数；选择不唯一时要求进一步约束，AI 不能任意取第一个结果。
5. 支持局部图补丁和影响查询；保持无关节点 ID、人工插入特征及组件覆盖。每次修改以最新 revision 为依据。
6. 将人工确认的需求断言和核心有效性检查作为独立验证依据。AI 可以提出补充检查，但不能为使结果通过而删除或放宽已有验收要求。
7. 设置每次任务的计算/修改/重试预算，区分可重试错误、需要调整参数、需要澄清和能力不支持。禁止无界重试或静默增大修复容差。
8. 改进失败呈现：显示失败特征、原因、仍有效的草稿部分、影响范围与可选择的修正；用户可在任意检查点接手。

### AI 评估集

至少覆盖：从零建模、尺寸关系、机械特征、曲面构造、人工修改后的接续、语义选择歧义、约束冲突、组件检索/复用、能力不支持和中途取消。对同一任务多次运行，记录成功率、修改轮次、计算时间和未授权改变，单次成功不作为稳定性证明。

分别报告：几何有效性、需求符合度、人工修改保留、过程可编辑性、组件复用成功和调用成本。几何比较按容差与语义进行；不要求 AI 每次生成完全相同的合法特征图。

### 交付与验收

核心确定性回归与关键演示任务全部通过；真实 AI 任务达到 S01/S09 实测后确定的发布门槛。保护的设计要求、版本冲突和人工修改不能被静默覆盖。任务失败能够留下可检查的草稿和诊断，不损坏正式文档。

## 18. S15：实现 worker、故障恢复和性能强化

### 实现任务

1. 将 S02 的执行器实现替换为可选独立 `cad-worker`。主进程持有已提交文档与版本权威，worker 持有可重建的几何上下文和运行时句柄。
2. 定义协议版本、任务 ID、文档 revision、worker generation、进度、取消和结果类型；所有响应先检查归属与时效。
3. 默认每个内核上下文串行执行。按文档/隔离需求配置 worker，禁止不同任务无保护地共享可变内核形体。
4. 协作取消与硬超时分开：前者在支持的算法/阶段检查取消；后者终止对应 worker 并恢复其负责的上下文。不得强杀持锁线程。
5. 崩溃恢复从已提交图、资产和有效检查点重建；未提交草稿标记失败可重试。验证幂等记录与提交持久化的一致性。
6. 大网格使用二进制传输或共享内存，定义长度、资源归属和释放协议；按帧预算分批上传显示数据，避免 UI 长时间阻塞。
7. 优化增量计算、网格 LOD、参数拖动防抖、任务合并与缓存上限；精度降低仅作用于明确的预览策略，正式提交按声明策略重新验证。
8. 算法脚本的进程、资源和可访问依赖单独控制。进程隔离不等于权限沙箱；若不具备有效的文件/网络访问限制，首版只运行固定的可信脚本，不开放任意 AI 代码执行。
9. 添加大输入、退化模型、内存预算、超时、进程退出和退出清理的故障注入测试。

### 交付与验收

在布尔、曲面操作和离散化过程中结束 worker，应用仍可操作，已提交工程可恢复。旧句柄和迟到结果被拒绝；连续取消/重开文档不泄漏资源。给出固定硬件、模型规模、冷/热缓存条件下的性能报告，不以简单模型的结果外推所有模型。

## 19. S16：验证真实的第二精确几何后端

### 实现任务

1. 根据 S01 的 SDK 选择和 S05 起的验证结果，实现第二后端 adapter。使用相同公共类型、命令和操作 schema，仅后端模块依赖其原生类型。
2. 先完成上下文、能力查询、生命周期、基元、拉伸/旋转、布尔、曲线/曲面构造、查询与离散化的约定公共子集。
3. 将已有参数化图在新分支使用目标后端重放；遇到缺失能力时报告具体节点和能力，不能自动转为网格来完成精确模型任务。
4. 比较单位、方向、实体数量、几何有效性、体积/面积及任务要求；拓扑面数和编号差异不自动判为不兼容，也不忽略语义选择失效。
5. 明确不同后端的操作历史质量。无法迁移的引用要求重新解析或指定，记录转换诊断。
6. 另外验证 STEP 几何转移路径，结果以导入特征表示；不宣称通过 STEP 恢复完整特征历史。
7. 检查上层代码是否出现针对后端的分支。必要差异应在 capability/操作策略中显式表达，不把内核类型泄漏给 UI、脚本或 AI。

### 交付与验收

第二真实后端通过已声明公共子集的契约测试，以及至少一个机械和一个曲面代表样件；这两个样件只使用双方支持的公共操作。高级能力差异通过能力矩阵说明。没有真实后端验证时，发布声明应限定为“OCCT 已实现、预留扩展接口”，不能声称已验证多内核替换。

## 20. S17：完成发布验收与使用文档

### 实现任务

1. 汇总已支持、受限支持和未支持的操作/输入范围，固定 SDK、后端、操作 schema、组件及工程格式版本。
2. 完整回归机械、曲面、人机交替编辑、组件跨工程复用、后端兼容、工程恢复和应用集成。

4. 验证旧工程迁移、新工程保存重开、依赖资产缺失、非法组件版本和内核版本不兼容的明确行为；不能在缺失依赖时悄悄用缓存冒充可编辑模型。
5. 交付安装包、运行库清单、版本诊断、示例工程、SDK 文档、节点说明、AI 工具说明和组件编写指南。
6. 在干净机器验证安装与启动、两类样件、人修改和 AI 连接、保存/导出、组件复用与 worker 恢复。首版 Windows，其他平台单独验收。

### 完成定义

用户能够从自然语言创建两个领域的模型，检查并修改过程/结果，要求 AI 接续修改，然后把过程在另一工程中复用。每项能力有受支持范围和验证依据。发布说明不将“可调用接口”“可显示网格”视为“完整支持建模”。

## 21. 首版核心接口和职责清单

以下作为实现拆分清单；具体名称可调整，职责保持稳定。

| 接口/模块 | 关键职责 | 不应承担 |
| --- | --- | --- |
| `CadDocument` | 主数据、当前 revision、已提交快照 | 内核原生拓扑和场景对象生命周期 |
| `EditDraft / CommandDispatcher` | 局部补丁、检查、事务和幂等 | 直接写入已提交形体 |
| `OperationRegistry` | 操作版本、类型、能力和描述 | 用户当前参数或几何缓存 |
| `GraphEvaluator` | 依赖、失效传播、执行与结果验证 | 通过 UI 节点位置决定计算顺序 |
| `SelectionResolver` | 语义选择、历史映射、歧义报告 | 静默使用面/边遍历索引 |
| `IGeometryBackend` | 几何运算、查询、有效性和离散化 | 工程参数、用户权限、AI 对话 |
| `ISketchSolver` | 草图约束求解和诊断 | 全局模型图调度 |
| `ComponentRegistry` | 版本、依赖、实例与变体 | 隐式升级所有实例 |
| `ProjectStore` | 工程、资产、迁移和原子保存 | 用网格替代精确输入资产 |
| `IModelingExecutor` | 任务、取消、执行隔离和恢复 | UI 修改语义或重复提交命令 |
| `CadDocumentController` | 人工交互、视口事件和文档事件同步 | 第二套特征主数据 |
| `CadToolDispatcher` | AI 工具 schema、权限和命令桥接 | 模型供应商特有的几何规则 |

所有入口共享的提交路径为：命令合法性检查 → 草稿依赖求值 → 几何/设计要求验证 → revision 检查 → 原子发布。查询、预览和导出按各自权限和副作用独立处理。

## 22. 验证矩阵和里程碑

### 人员与估算

参考 5 人团队：核心/运行时 1 人、几何与草图 1 人、曲线曲面与交换 1 人、Godot/交互 1 人、集成/测试/AI 工具 1 人。模块负责人负责实现和模块验证，集成人员不承担全部测试编写；S02/S08/S09 的绑定和 AI 工具由核心与集成协作。

在 SDK 可获得、团队具备几何开发经验、首发 Windows 和输入范围受控的前提下，M1 可按第 8–12 周、M2 第 16–24 周、M3 第 24–36 周做初始里程碑估算；均从实际开工计算，为累计时间，不能相加。需要在 M0 和 M1 后分别重新估算。复杂直接编辑、广泛 G2 曲面、第二后端差异和长期组件迁移可能增加投入，不能据此承诺通用商业 CAD 的全面覆盖。

### 第一轮建议开发提交

按依赖拆成可独立审阅的开发提交，首轮不一次性加入大量操作：

1. 样件、验收断言、依赖清单与独立构建骨架。
2. 单位/ID/引用类型、节点 schema 和诊断协议。
3. 文档快照、命令、草稿事务、revision 与幂等。
4. OCCT 机械最小链和曲线/放样最小链，附几何验收。
5. 图求值、增量更新、参数表达式、保存和回放。
6. 语义引用、操作历史与参数变化回归。
7. Python/GDScript facade、Godot 最小参数面板与预览。
8. 基础组件提取/实例化与 AI 最小工具集，完成 M1 演示。

每个提交更新能力矩阵和相关文档，并运行与变化有关的验收；只有构建成功不算建模能力完成。
