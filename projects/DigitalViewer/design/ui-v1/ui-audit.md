# DigitalViewer UI 工业级评审

评审对象：`multi-viewport.html` 当前版本（右栏属性 + 底部脚本；v1 无 AI）。
评审日期：2026-10-26。

## 结论

**视觉与信息架构方向合理，但当前仍是高保真交互原型，不是工业级交付。**

- 概念/交互原型：约 **7.5 / 10**
- 工业级生产就绪度：约 **4.5 / 10**
- 不建议按“可直接交付工业客户”的标准验收；需要先完成 P0 项。

当前最突出的问题不是布局，而是**可访问性、脚本安全、AI 状态完整度、错误恢复和跨平台一致性**。

## 评分

| 维度 | 分数 | 判断 |
| --- | ---: | --- |
| 信息架构 | 8.0 | 每视口图层树、右侧属性、AI/脚本应用级，职责基本清楚 |
| 视觉层级 | 7.5 | 深色主题统一，面板层级明确；字过小 |
| 一致性 | 6.5 | 平台拆分明确（桌面/Web 多视口、移动单视口），但设计令牌与组件需共享 |
| 可访问性 | 3.5 | 字号、对比度、树键盘语义、焦点管理不足 |
| 安全性 | 3.0 | 多视口脚本没有首次运行信任/权限确认；AI 工具审批缺失 |
| 错误与恢复 | 3.5 | 缺少失败、离线、重试、部分加载、未保存状态 |
| 键盘与效率 | 4.5 | 只有少量快捷键，无命令面板、无撤销中心 |

| 文档 | 8.0 | 规范详细，但与原型存在偏差 |

## 做得好的部分

1. **职责分离**：属性跟随活动视口；AI/脚本应用级，不再显示目标视口。
2. **面板可组合**：属性/AI/脚本都可关闭、独立、停靠；右栏 A 布局在 1440 下仍保留约 1076 px 视口。
3. **每视口隔离**：递归分割、独立世界、独立图层树、拖放共享数据的模型清楚。
4. **相机归位**：相机模式收进树顶部 `相机` 对象，不再占用全局顶栏。
5. **空态与折叠**：6 视口下标题栏工具收进菜单，空视口有添加入口。
6. **设计令牌**：颜色、间距、组件基本统一，`prefers-reduced-motion` 已处理。

## P0：不解决不能称工业级

### 1. 可访问性基线不达标

**证据：**

- `multi.css` 仍存在 `7px / 8px / 8.5px / 9px` 的活动 UI 字号；树元信息、状态栏、chip 明显偏小。
- `--text-3: #6e8088` 在 `--surface: #10181e` 上对比度约 **4.36:1**，在 `--surface-raised: #162128` 上约 **3.98:1**，低于 WCAG AA 普通文本 4.5:1。
- 图层树行是 `div`，没有 `role="tree/treeitem"`、`tabindex` 或方向键导航；键盘用户无法遍历树。
- 动态面板/模态缺少焦点陷阱和返回焦点策略；Toast 没有 `aria-live`。
- 顶栏紧凑模式隐藏按钮文字；`属性/AI/脚本` 已补 `aria-label`，但这是单点修复，不是系统性方案。

**要求：**

- 正文 ≥ 12 px；元信息 ≥ 11 px；关键操作 ≥ 12 px。
- 普通文本对比度 ≥ 4.5:1；大字/图标 ≥ 3:1。
- 树支持 `↑/↓/←/→/Enter/Space`，有明确的 `aria-expanded/aria-selected`。
- 所有图标按钮都有可访问名称；焦点顺序可预测；模态焦点陷阱。
- 200% 缩放和 1.5 倍系统字体下不截断关键字段。

### 2. 原生脚本没有工业级安全门

**证据：**

- `multi-viewport.html` 中没有首次运行信任确认；点击“运行”直接执行。
- 权限范围、风险条、执行来源、脚本文件来源、会话结束清理提示缺失。
- 关闭脚本会直接停止并丢弃未保存编辑，没有 dirty 提示。

**要求：**

- 首次运行必须显示信任确认：脚本名、大小、权限、风险、取消/我信任并运行。
- 脚本编辑器有 dirty 状态；关闭/切换文件前确认保存或丢弃。
- 明确“脚本拥有应用权限；同步死循环无法通过停止按钮中断”。
- 记录来源、哈希、执行时间和退出原因。

### 3. 内部 AI 已移出 v1（不适用）

v1.0 不内置 AI 助手，因此本项不作为 v1 验收阻塞。内部 AI 只保留为 v1.1 候选；如恢复，必须重新满足：

- 连接、模型、凭据、超时、预算；连接测试状态。
- 发送/停止/重试/重新生成；流式与错误状态。
- AI 只通过 GDScript 与场景交互，不生成/读取 JSON；草案必须由用户审查、确认信任后手动运行，绝不自动执行。
- 脚本 diff、权限清单、执行结果、错误定位和撤销入口；上下文用量与清理。

v1 的 AI 相关交付只有：脚本面板、信任门、本机 MCP、外部 AI 接入文档。

### 4. 错误、离线、部分失败没有设计

**证据：**

- 图层状态只有 `loading/ready/paused`，没有 `failed/partial/offline`。
- 没有瓦片失败、DEM NoData 回退、影像 401/403/CORS、网络断开的视口级提示。
- 诊断面板是静态演示数据；没有从错误到重试/定位的闭环。

**要求：**

- 每个视口有可收起的错误条/角标；错误不遮挡场景。
- 图层级失败状态、错误码、重试、禁用/移除。
- 离线/弱网状态；请求预算和降级提示。
- 关键错误提供“复制诊断信息”。

### 5. 破坏性操作缺少确认或撤销

**证据：**

- 图层“移除”立即生效，只弹 Toast；没有确认或撤销。
- 脚本关闭会停止运行并丢弃编辑；没有确认。
- 视口关闭/分割等操作缺少一致的撤销模型。

**要求：**

- 删除图层：确认或 5 秒撤销 Toast（含动作按钮）。
- 关闭脚本/视口：dirty/运行中状态确认。
- 统一 Undo/Redo 模型，至少覆盖删除、显隐、排序、脚本编辑。

### 6. 自动化 API 缺失（P0）

**证据：**

- 场景能力只通过脚本 UI 暴露；外部 AI 无法直接通过 MCP 控制 DigitalViewer。
- 设置页只有 MCP 端点设计，没有真实工具、权限、令牌和审计。
- 若把内部 AI 作为核心，会重复 Harness 的模型、工具、审批和错误恢复，且超出 v1 范围。

**要求：**

- 本机 MCP + 同一脚本 API；`scene.read` / `script.run` / `capture` 权限。
- 外部 AI 与场景 Copilot 共用脚本、检查点、审计；两者都只操作运行时场景，不接触产品代码、仓库、终端或构建。
- Web 不暴露本机 MCP；移动端 AI 只读。

## P1：工业级体验差距

0. **跨平台设计系统**：`index.html` 是移动单视口壳，`multi-viewport.html` 是桌面/Web 多视口壳；平台拆分是有意的，但两套壳的顶栏、属性、AI/脚本、状态与诊断组件仍有重复实现。共享颜色/间距/字体/按钮/字段/空态/错误态，视觉回归同时覆盖 390 与 1440。
1. **图层树在明亮影像上的可读性**：无背景是产品要求，但需要更强文字阴影/局部 scrim/自动对比度，不能只靠深色示例底图。
2. **图标可发现性**：视口标题栏关键工具图标化，缺少可见标签/分组；建议 hover tooltip + 首次使用提示。
3. **状态栏语义**：`请求 6` 无单位；FPS/Resident 是静态演示值；需要真实指标、时间窗口、错误计数。
4. **命令面板/快捷键**：目前只有 `Esc`、`Ctrl+Tab`、`Ctrl+1..9`、`Ctrl+\`；缺少 `Ctrl+K`、面板开关、树导航、属性焦点跳转。
5. **多语言**：多视口页只有中文；单视口有中英切换；需要统一 i18n 和长文本策略。
6. **高 DPI/窄宽/长名称**：没有 200% 缩放、长图层名、长 URL、长错误信息的验收用例。
7. **极端视口数量**：6 视口可用，但 8/12 时缺少软警告、布局建议和性能降级说明。
8. **脚本编辑器**：无行号、语法高亮、错误行定位、打开/保存、场景树/只读属性；当前是 `contenteditable pre`。
9. **AI 上下文与权限**：应用级后更需要明确“当前工程范围”，避免用户误以为能操作所有视口。
10. **自动化质量门**：没有 axe/对比度/键盘/视觉回归测试；当前 Puppeteer 只验证布局与交互。

## P2：打磨项

- 面板拖拽/缩放的光标、吸附、双击恢复默认。
- 面板独立窗口的最小/最大尺寸与屏幕边界。
- 空态、加载骨架、错误插画的统一语言。
- 数字/单位排版（tabular-nums、单位空格、千分位）。
- 动效节奏与 reduced-motion 全覆盖。
- 文案统一（“视口/窗口/面板/停靠/独立”）。

## 建议的验收门

工业级交付前至少满足：

- [ ] WCAG AA：文本对比度、焦点可见、键盘可达、200% 缩放。
- [ ] 树/面板/模态完整键盘操作与焦点管理。
- [ ] 脚本首次信任、权限说明、dirty 保护、风险条。
- [ ] AI 连接/停止/重试/工具审批/错误状态。
- [ ] 图层失败/离线/重试/诊断闭环。
- [ ] 删除可撤销；关闭运行中/未保存内容需确认。
- [ ] 单/多视口共用一套 shell。
- [ ] 6/8/12 视口、1100/1440/1920、200% 缩放视觉回归。
- [ ] 真实数据下的性能与错误注入测试。

## 建议顺序

1. 统一 shell + 可访问性基线（字体、对比度、树键盘、焦点）。
2. 脚本安全门 + dirty 保护。
3. AI 状态机 + 工具审批。
4. 错误/离线/重试 + 破坏性操作撤销。
5. 命令面板、快捷键、i18n、状态栏真实指标。
6. 自动化 a11y/视觉回归。

## 备注

本轮已顺手修复一个一致性问题：AI 发送后的模拟回复原先仍写“只作用于当前视口”，已改为应用级语义。其余 P0 项需要产品/实现共同决策，未在本轮直接改动。
